## Why the benign cases don't false-positive

- **`legit-package.json`** — has `scripts` and various build commands, but
  the `preinstall` field is absent entirely. The manifest rule requires
  both `"scripts"` and `"preinstall"` *and* either the tools-path regex
  or one of the attacker handles. None of them are present. IOC rule
  fails for the same handle-absence reason.
- **`small-tool.elf`** — has the ELF magic and ELFCLASS64 byte, but its
  filesize (~64 KiB) is well below the 700 KiB lower bound on the dropper
  rule. Even if it contained `UPX!`, the size filter would reject it.
- **`random-200k.bin`** — urandom. The probability of forming the ELF
  magic at offset 0 is 2⁻³² ≈ negligible.

## Caveats

- **Synthetic specimens.** `package-asteroiddao.json` and `ioc-dump.txt`
  are modelled on JFrog's published IOCs; `tools-setup.elf` is a minimal
  ELF64 header + padding + the UPX!/c2 anchors. They prove condition
  logic, not byte-level fidelity to the real ~976 KiB Rust dropper.
- **Linux-only payload.** The ELF rule by design only matches Linux
  binaries; the IronWorm operator has not (yet) shipped Windows or macOS
  variants. If they do, add a Mach-O / PE specimen rule.
- **C2 endpoint and BIP-39 seed live inside the UPX-packed payload.**
  Most on-disk samples will be packed; `$c2_endpoint` and `$bip39` will
  only fire on memory dumps or unpacked specimens.
- **IOC rule is `severity = "high"`** — public threat-intel writeups
  (including this transcript) contain the same handles and seed phrase
  and will pop the rule. Triage by file context.
- **Wallet seed is the operator's, not the victim's.** Anyone with the
  recovered BIP-39 can sweep funds from `0x7e28…a4d6`; treat that string
  with the same caution as any other credential.

## Not covered

- **Memory-only rootkit artefacts.** The eBPF rootkit's data structures
  (process-hiding maps, syscall filters) are not on-disk indicators; pair
  with runtime hunting (`bpftool prog list` from a known-good initramfs,
  or kernel-side BTF inspection).
- **Tor C2 traffic** — out of scope for filesystem YARA. A Snort rule on
  Tor circuit establishment from CI runners is the closest sibling, but
  not included in this repo because the FP load on mixed environments
  outweighs the detection benefit.
- **Self-propagation via stolen Trusted Publishing tokens.** Catching new
  victim publications requires npm-registry-side monitoring (e.g.
  publisher-account anomaly detection) rather than YARA.
