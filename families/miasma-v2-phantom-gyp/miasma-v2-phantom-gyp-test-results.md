## Why the benign cases don't false-positive

- **`benign/binding.gyp`** — real `node-addon-api` build manifest. Lists C++
  source files in `sources`, uses `<!@(node -p "require('node-addon-api').include")"`
  for include-dir expansion. The trigger rule requires either the verbatim
  `<!(node <name>.js > /dev/null` pattern *or* the co-occurrence of one of
  `"sources"/"inputs"/"actions"` *and* a `<!(<cmd>)` substitution where
  `<cmd>` is `node <file>.js` or one of `bash|sh|curl|wget|python`. The
  benign uses `<!@(...)` (array-form expansion) plus `node -p`
  (one-liner), not the malicious shape. The `$action_node` regex anchors
  on `<!\s*\(\s*node\s+<file>\.(m?js|cjs)`; `node -p "…"` doesn't match.
- **`benign/normal-index.js`** — large bundle, no campaign markers, no
  Bun-chain anchors, no exfil-path, no credential-target list of three or
  more co-occurring tokens. The payload rule's three branches all fail.
- **`benign/random.bin`** — urandom.

## Lesson worth keeping

Two self-inflicted FPs surfaced on the first iteration. **(1)** The benign
`normal-index.js` had a comment starting "Contains nothing matching the
Phantom Gyp campaign markers…" — the literal phrase `Phantom Gyp` in that
comment matched the IOC rule's `$technique_name` anchor. Rewrote the
comment to avoid the literal. **(2)** `build-payload.py` embedded the
campaign markers as Python string literals (it has to — that's its job)
and so the IOC rule fired on the helper itself. Moved the helper out of
`specimens/` to the family root so the smoke-test corpus scan doesn't
sweep it. Both are the same lesson from the Miasma original test
transcript, recurring here.

## Caveats

- **SLSA-provenance forgery is not on-disk-detectable.** The poisoned
  packages ship valid Sigstore-signed attestations because the worm
  itself drives the Fulcio/Rekor flow with stolen npm publish tokens.
  Verifying a poisoned package's signature returns success. Defence
  here is **not** at the YARA layer — it's pre-publish CI hygiene
  (rotate npm Trusted Publishing tokens, alert on publish from
  unexpected workflow_id), and post-publish anomaly detection on the
  npm registry side (sudden binding.gyp introduction in a previously-
  pure-JS package).
- **Bun-chain anchors will age.** The current campaign pins Bun
  v1.3.13. Future variants will rotate. The behavioural rule branches
  on `bun_release` OR `bun_run` OR `tmp_b`, so any one survives — but
  if all three rotate, only the campaign-unique strings remain as the
  rotation-resistant fallback.
- **Synthetic payload specimen.** ~280 KiB JavaScript with the verbatim
  markers and credential-target list, padded to land in the rule's
  size band. Proves condition logic; not byte-equivalent to the real
  ~4.5 MiB heavily-obfuscated dropper.

## Not covered

- **Sigstore Fulcio cert request flow** — runtime/network signature,
  not filesystem. A WAF or proxy rule on `*.sigstore.dev` certificate
  requests from CI runners that aren't supposed to be signing is the
  sibling control.
- **GitHub Actions workflow injection** as persistence — Phantom Gyp
  drops `.github/setup.js` and modifies `.github/workflows/*`. A
  separate rule on `.github/workflows/*.yml` injection would catch
  that specifically; out of scope here.
- **Cisco SD-WAN CVE-2026-20245** — the other big item from today's
  cyber digest. No public PoC or exploit-file IOC yet, and the
  delivery (authenticated CLI on the management plane) is encrypted
  protocol surface with no clean YARA target. Watch for Cisco's
  follow-up advisory or Mandiant's technical writeup; revisit then.
